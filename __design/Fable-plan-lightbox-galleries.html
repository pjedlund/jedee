Fable plan · rank 3 — the next feature in the lightbox arc

Photo galleries: several photos in one post, prev/next inside the lightbox

The lightbox shipped for single images in early July. This adds galleries: a photo post lists several images in its frontmatter, they render as a thumbnail grid, and clicking any of them opens the same lightbox — now with arrows to flip between them, plus the zoom and swipe you already have.

The fork in the road, resolved

Two gallery mechanisms exist in the house: the starter theme's dormant dialog-based gallery (thumbnails opening a plain dialog — no zoom, no swipe) and the PhotoSwipe lightbox built this month. This plan builds on PhotoSwipe. It matches how every other image on the site already behaves, and — the lucky part — the lightbox script already understands galleries: it treats every image link inside its wrapper as one navigable set. The dialog machinery stays in the repo untouched; whether to retire it is your later call.

How authoring looks

---
photo:
  src: /assets/images/photos/harbor.jpg
  alt: The harbor at dusk
gallery:
  - image: /assets/images/photos/harbor-2.jpg
    alt: Fishing boats
    caption: The morning after
  - image: /assets/images/photos/harbor-3.jpg
    alt: The pier
---

The gallery: field shape is the one the photo spec already anticipated. A {% gallery %} shortcode renders it, so post bodies can use it too if wanted later.

What gets built

PieceWhat it does
New photo-gallery.webcThe wrapper component: holds the image links, loads the same lightbox styles and script.
One line in photo-lightbox.jsTeaches the existing lightbox element its second name, photo-gallery. (There's a JavaScript trap here the plan spells out — the naive one-liner crashes.)
A gallery shortcode in image.jsTurns the frontmatter list into responsive thumbnails, each a plain image link — deliberately not one lightbox component per image, which would break the prev/next.
photo.njkRenders the gallery under the photo post's text when gallery: is set.
Thumbnail grid CSSReuses the house grid composition; styled per CUBE conventions.

Gotchas already scouted

  • Nesting one lightbox component per image gives N separate lightboxes with no arrows between them — the gallery's images must be plain links inside one wrapper.
  • The wrapper component's existing template hardcodes exactly one link, so it can't be reused as the gallery shell — hence the new sibling component.
  • Registering the same element class under a second name crashes; a one-line subclass is the fix.
  • Markdown mangles the component markup unless the output starts with a plain <div> — same trick the single-image shortcode already uses.
  • Captions show under the thumbnails on the page; captions inside the lightbox overlay need a plugin we don't ship — out of scope, on purpose.
  • Each visible gallery image gets the u-photo microformat class (data for webmention parsers, not styling).
  • Book/film/album covers deliberately don't get the lightbox — decided earlier, not reopened here.

Done means

  • A test photo post with three gallery images: thumbnail grid renders, clicking opens the lightbox, arrows flip between all three, zoom/swipe/Esc all work.
  • Existing single-image lightboxes produce byte-identical output to before.
  • The photo spec's gallery paragraphs updated to describe what was actually built.
