Fable plan · rank 1 — do this first

Steady masonry front page (no layout shifts)

The tiles on the front page jump into place a moment after the page paints. That jump is the layout-shift penalty you spotted in Lighthouse. The fix: let CSS do the masonry instead of JavaScript — the tiles then land in their final spots on the very first paint, and the shift score drops to zero.

Why it shifts today

The wall is a <custom-masonry> component. It first lays the tiles out as a normal grid, and only after the first paint does its JavaScript pull each tile up under the one above it. Moving things after paint is a layout shift — no amount of tuning fixes that; the JavaScript pass has to go.

The chosen approach: CSS columns

CSS has a native multi-column layout (columns) that gives the masonry look with no JavaScript at all. Two properties on the wall, one on each tile. It also keeps every tile's exact proportions at any screen width, which the alternative techniques don't.

One trade-off, accepted for now: with columns, the tiles read top-to-bottom per column instead of left-to-right. Today the wall is decorative placeholder blocks (the real cards wait on the Penpot card design), so order doesn't matter yet. When real cards land, we revisit — there's a fallback technique documented in the plan if left-to-right ever becomes a must.

Scope — only the front page

The same masonry component also wraps the archive pages, tag pages, and the events page. Those hold real text cards, which are a different (harder) problem — they stay untouched in this pass. The component stays in the codebase; it just stops being used on the front page.

Gotchas already scouted (so nobody trips on them)

  • In a columns layout, gap only spaces the columns — the vertical space between tiles needs a bottom margin on each tile. Forgetting this makes the tiles touch.
  • break-inside: avoid on tiles, or a tile can split across two columns.
  • Lighthouse must run against a production build — the dev server serves drafts, unminified files, and shows the hidden nav.
  • Running npm run build wipes the folder the dev server serves — known quirk, restart the dev server after.
  • A perfect 400 is impossible until launch: the SEO category fails on purpose while the site carries the soft-launch "don't index me" tag. Expected result now: three 100s, SEO failing only on that one audit.
  • Don't delete the masonry component files — four other pages still use them.
