Fable plan · rank 2 — highest impact, runs right after the masonry fix

1.0.0 go-live: drop the "don't index me" tag, show the nav, start sending webmentions

The site has quietly lived on johanedlund.se since the end of May — invisible to search engines and with the nav hidden. Everything behind it (Micropub, incoming webmentions, feeds, content pipeline) is already live and verified. Launching is now two switches in one file, a version bump, a careful verification pass, and a short checklist that's yours alone.

You decide when. This plan executes the launch; it doesn't decide readiness. Suggested order: run the masonry fix first so the front page is at its best when the crawlers arrive — and because the perfect Lighthouse score only becomes possible once the "don't index" tag is gone.

The code part (an agent can do all of it)

WhereWhat
src/_data/meta.jsnoindexSite: true → false (search engines welcome) and hideNav: true → false (nav shows everywhere). The breadcrumb switch stays as it is.
package.jsonVersion 0.9.0 → 1.0.0 (with the lock file kept in step).

Then a full verification pass on a production build: the robots tag is gone from every page, the nav markup is actually in the built HTML, the sitemap is intact, unit tests pass, and — importantly — the pa11y accessibility suite runs with the nav visible in a production-style build for the first time ever. If the nav surfaces accessibility complaints, they get fixed using the navigation pattern the site is built on, not ad-hoc. Everything merges to main and stops there.

Your checklist (the agent prints it, you do it)

  1. Push main. Netlify deploys; no settings need changing — the site already builds on the apex domain.
  2. Spot-check the live site: view source on the front page — no robots tag, nav visible; click through the mega-menu.
  3. Turn on outgoing webmentions at webmention.app: sign in with johanedlund.se (the GitHub rel=me sign-in — already proven to work), register https://johanedlund.se/feed.xml. It then checks hourly and sends webmentions for the links in new posts.
  4. Heads-up: only posts published after registration send automatically. Older posts can be sent by hand via webmention.app/check?url=….
  5. Test sending against webmention.rocks first, then a real like or reply to someone's IndieWeb site.
  6. Optional: a Netlify "deploy succeeded" webhook to webmention.app makes sending instant instead of hourly. Optional: tag the release 1.0.0 in git. Then: tell people.

Gotchas already scouted

  • The nav is always visible on the local dev server — "it looks fine in dev" proves nothing. Every check must be against a production build.
  • Posts marked visibility: unlisted keep their own per-post "don't index" tag after launch — that machinery must not be touched. (There are currently no published unlisted posts, so nothing visible changes.)
  • The version bump must not use npm version — it silently creates a git tag; tagging is your call.
  • If the per-section feeds plan runs, it should run before launch — it moves the podcast feed's address, which is free while nobody is subscribed and disruptive afterward.

Done means

  • Production build: robots tag gone, nav present on every page, version 1.0.0, all tests green.
  • Merged to main, unpushed, with your six-step checklist printed at the end.
  • Lighthouse SEO on the front page reads 100 against the local build.
