post-type spec

Note

Shipped · Phase 2 · singular note / plural notes · extracted from live code 22 May 2026

A Note is a short, title-optional post — a thought, observation, or brief reaction, often linking out to something worth reading. The IndieWeb's canonical short-form post type: no headline required, no article-length commitment.

1. Singular / plural identity

Note is asymmetric: the type is singular, the URL namespace is plural. The Eleventy collection is named with the singular (collections.note), but the folder, URL, archive, and feed all use the plural.

Note the mismatch: the folder is notes/ but its data file sets category: "note", and the collection registered from that category is note (singular). Don't "fix" this — the layout alias, collection, and category are all singular by design.

2. Naming & aliases

JEDEE's short-form type is named Note (singular) / Notes (plural), following IndieWeb convention for a title-optional, freeform short post. The name is generic by intent: a Note can be an observation, a link reaction, a brief aside — anything that doesn't warrant an Article.

TermStatusWhere it appears / why
note / noteschosen nameType, layout, collection, URL, archive, feed, nav (see §1).
p-name (absent)IndieWeb implicationA Note omits a visible p-name; the h-entry root has no headline property. This is correct IndieWeb behavior for a title-optional short note.

4. Frontmatter

The shape below is the live sample (src/posts/notes/Affinity Studio.md) — the authoritative authoring surface today. A second sample (test.md) adds an updated field, documented in the table.

---
title: Affinity Studio                                          # optional
description: Completely free version with both vector, bitmap and photo editing.
date: 2025-03-04
tags:
  - design
draft: false
---
FieldReq?Role
titleoptionalHeadline; falls back to slug. Title-optional type — a Note without a title is valid IndieWeb practice.
daterequiredPost timestamp (sort + dt-published).
descriptionrecommendedCard excerpt (card-notes.njk renders it via markdownFormat) and feed summary.
tagsoptionalTopic tags (e.g. design). Not the category.
draftoptionalWhen true, the card shows a "draft" badge; post is still built.
updatedoptionalLast-modified timestamp; rendered by entry-header.njk as "Updated: <date>".

category, layout, and permalink are not authored per-post — they come from the folder data file src/posts/notes/notes.json (see §1 and §12). The folder data file also sets tags: "posts" (the system tag) so notes appear in the global posts collection; this is separate from per-post topic tags.

5. Microformats (µf2)

Emitted by src/_layouts/note.njk. A Note is a short-form h-entry with body content only — no syndication-target property like u-listen-of or u-like-of:

<div class="e-content">
  {{ content | safe }}
</div>
PropertyClassFrom
Bodye-contentpost content
Publisheddt-publisheddate (via entry-header → date.njk)
Authorshiph-entry / h-card / u-authorhidden block, meta.author

h-entry nesting caveat: the only visible h-entry in the layout is the hidden authorship block; the .e-content sits outside it, so a strict parser won't tie the body to the entry. Accepted for v1 (webmention sending isn't wired up). Slated for the webmention milestone.

No p-name: entry-header.njk only renders an <h1> when title is set. A Note without a title correctly emits no p-name, which is valid IndieWeb behavior for a short note post.

6. Card — bespoke card-notes.njk

Note has a dedicated card partial (src/_includes/partials/card-notes.njk). It is one of only two post types with a bespoke card (the other is Reading). The card renders a <custom-card clickable> WebC component — no img-square, no image slot — styled via css/custom-card.css.

SlotContent
headlineitem.data.title, linked to the post URL; level controlled by headingLevel (defaults to h2)
datedate via date.njk; prepended with a "draft" badge (data-button-variant="tertiary") when draft: true
tageach tag except "notes" (the filter literal in the card), rendered as <span class="button" data-small-button>; hidden if showTags is false or there is only one tag
contentitem.data.description piped through | markdownFormat | safe — supports inline markdown in the description

No image slot. Unlike card-blog.njk, the Notes card carries no image or album-art column. This is intentional: Notes are text-first.

Tag filter literal. The card excludes the tag "notes" (hardcoded in the partial), while the folder data file injects tags: "posts" as the system tag. The two strings are different; a Note with neither tag showing up is a no-op: only topic tags the author adds (e.g. design) are rendered.

7. Archive page config

src/pages/notes.njk drives the listing through the shared archive-listing.njk partial:

pagination: { data: collections.note, size: 10 }
permalink:  notes/[page-N/]index.html
cardPartial = "card-notes.njk"
masonryLayout = "50-50"
collectionToPaginate = collections.note
paginationMetaKey = "blog"

Pagination size is 10 — larger than the default 3 used by Jams and Reading — reflecting that Notes are short and many fit per page comfortably.

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (notes.xml.njk → feeds/atom-body.njk) and JSON Feed (notes.json.njk → feeds/json-body.njk):

# notes.xml.njk
permalink: /notes/feed.xml
feedCollection = collections.note
feedTitle = "Notes"
feedDescription = "Short thoughts and observations."
feedSelfUrl = "/notes/feed.xml"
→ includes feeds/atom-body.njk

# notes.json.njk — same vars, with:
permalink: /notes/feed.json
feedSelfUrl = "/notes/feed.json"
→ includes feeds/json-body.njk

The permalink: frontmatter (not the filename) controls the output path.

12. Collection registration (wiring)

// src/_config/collections.js
const byCategory = cat => collection =>
  collection.getFilteredByGlob('./src/posts/**/*.md')
    .filter(item => item.data.category === cat)
    .reverse();
export const note = byCategory('note');

// eleventy.config.js
import { ... note ... } from './src/_config/collections.js';
eleventyConfig.addLayoutAlias('note', 'note.njk');
eleventyConfig.addCollection('note', note);

Category names never enter tags, so "note" does not pollute /tags/.

13. Authoring — Web Clipper & source archiving

Notes are typically authored by hand in the vault — short posts that don't require a structured clip. However, a Clipper template does exist, and it serves a different flow than direct Note publishing:

_resources/note-to-_sources-clipper.json — source-archiving template

This template clips web pages into a reference-sources holding folder (posts/notes/_sources/), not directly into the publishable Notes collection. Its name makes this explicit: "note to _sources" — it saves a clipped web page as a research note inside _sources/, which is an Obsidian convention for raw-capture material that may later be drafted into a published Note.

{
  "schemaVersion": "0.1.0",
  "name": "Note to _sources",
  "behavior": "create",
  "noteContentFormat": "{{content}}",
  "properties": [
    { "name": "title",       "value": "{{title}}",                                    "type": "text" },
    { "name": "date",        "value": "{{date}}",                                     "type": "text" },
    { "name": "description", "value": "{{description}}",                              "type": "multitext" },
    { "name": "source",      "value": "{{url}}",                                      "type": "text" },
    { "name": "author",      "value": "{{author|split:\", \"|wikilink|join}}",        "type": "multitext" },
    { "name": "published",   "value": "{{published}}",                                "type": "date" },
    { "name": "tags",        "value": "clippings",                                    "type": "multitext" }
  ],
  "triggers": [],
  "noteNameFormat": "{{title}}",
  "path": "posts/notes/_sources/"
}
PropertyClipper sourceNotes
title{{title}}Page title.
date{{date}}Clip timestamp.
description{{description}}Page meta description.
source{{url}}Origin URL of the clipped page.
author{{author|split:", "|wikilink|join}}Author name(s), wikilinked for the Obsidian graph.
published{{published}}Publish date of the original article.
tags"clippings" (static)Marks the note as a raw clip, not a published post.

This is not the Note publishing path. The template targets posts/notes/_sources/, not posts/notes/. Files written here are not in the published collection — collections.note picks up src/posts/**/*.md with category: "note", and _sources/ files carry no category or layout (they'd inherit the Notes folder data file if they sat at posts/notes/, but they're one level deeper and presumably have no notes.json). The flow is: clip → _sources/ → author revises → moves/writes a publishable .md in posts/notes/ with the correct frontmatter by hand.

No triggers. The triggers array is empty — this template is invoked manually, not by URL pattern matching. It is a general-purpose web-page archiver.

_resources/types.json is the Obsidian vault-level property type registry, not a JEDEE template or clipper registry. It defines field types (text, multitext, date, number, checkbox) used across all notes in the vault, and is maintained by Obsidian itself.

14. Webmentions

Webmention is the IndieWeb's federated response protocol: likes, replies, and reposts from other sites arrive as cross-site comments. Nothing here is Note-specific — the plumbing is shared by every post type and Note inherits it through the base layout and entry-footer.njk. Discovery is shipped; receiving and sending are deferred to the webmention milestone.

PieceStateWhere
Endpoint discoveryshipped (Phase 1)<link rel="webmention" href="https://webmention.io/johanedlund.se/webmention"> in <head> via src/_includes/head/meta-info.njk (note uses layout: base).
Authorship h-cardshippedThe hidden h-entry block in note.njk carries u-url, p-name u-url rel="author", and a u-author h-card avatar so a receiver can attribute the post (§5).
Render slotwired, no-opnote.njk → entry-footer.njk → partials/webmentions.njk, currently an empty stub — safe to call while the renderer is empty.
Receiving / renderingdeferredThe webmention milestone wires a webmention.io fetch (via @11ty/eleventy-fetch, ~24 h cache); webmentions.njk then groups received mentions by type (likes / replies / reposts / mentions).
SendingdeferredOutgoing webmentions aren't wired, so a Note that responds to another post doesn't notify it yet.

h-entry nesting (§5). The only h-entry in the layout is the hidden authorship block; the visible .e-content sits outside it, so a strict parser won't tie the body to the entry. Harmless while sending is off; fix it when the sending side of the milestone lands.

15. Status & open items

  • Shipped in Phase 2 (the "align the 5 existing types" pass; Note is an original Eleventy Excellent type) — layout, bespoke card, archive, feed, nav, and sample posts all live.
  • Source archiving clipper (_resources/note-to-_sources-clipper.json) ships a general-purpose web-page archiver to posts/notes/_sources/. The authoring path for publishing a Note remains manual (hand-authored frontmatter). No dedicated Note publishing clipper exists. (open)
  • Webmentions — discovery + the no-op render slot are shipped; receiving/rendering, sending, and the h-entry nesting fix (§5) are deferred to the webmention milestone. See §14.
  • Micropub — no endpoint today; a future endpoint would write posts/notes/<slug>.md with a category: "note" payload. Sequenced after Phase 4.
  • Schema — BlogPosting is a stable fit for Note; no upgrade planned.
  • _sources/ convention — files clipped into posts/notes/_sources/ sit beneath the notes/ folder and would inherit the notes.json data cascade. Confirm that _sources/ either has its own data file overriding eleventyExcludeFromCollections: true, or that its files don't accidentally appear in collections.note. (open — verify)
