post-type spec

Watching

Shipped · Phase 2 · uniform singular watching · extracted from live code 22 May 2026

A Watching is a short post logging a film or show the author has watched — linking to its Letterboxd page, recording the rating and cast, and optionally writing a brief reaction. An IndieWeb "watch" post.

1. Singular / plural identity

Watching is symmetric singular throughout: the type name, folder, URL namespace, collection, layout, archive, and feeds all use the same word, watching. This is the opposite of Jam, which is asymmetric (singular type / plural URL). Watching behaves like Reading — every aspect uses the same form.

Contrast with Jam: jam type / jams/ URL is asymmetric by design. Watching has no such mismatch — every token is watching. Don't introduce a plural anywhere.

2. Naming & aliases

JEDEE's film-logging type is named Watching (present-participle form), matching Reading — both describe a consumption activity rather than curated endorsement. The IndieWeb calls this a watch post.

TermStatusWhere it appears / why
watchingchosen nameType, layout, collection, URL, archive, feeds, nav (see §1).
watchIndieWeb verb — kept in µf2There is no "watching" microformat property: the property is u-watch-of. Watching reuses IndieWeb's watch vocabulary.

4. Frontmatter

The shapes below are drawn from the two live samples (src/posts/watching/Birth.md and src/posts/watching/310 to Yuma.md) — the authoritative authoring surface today. Both were written by the Letterboxd Clipper (§13); field naming follows what the clipper emits. Note the minor drift between the two samples (e.g. scoreLB/rating and scoreMy/myRating) — these are the live inconsistencies; the canonical forward shape is what the clipper template produces (see §13).

---
title: "Birth"
description: "2004 reincarnation drama by Jonathan Glazer, starring Nicole Kidman."

  - "Jonathan Glazer"

  - "Lauren Bacall"

the entire way unfortunately. Made me want to check out more films by Jonathan Glazer.
FieldReq?Role
titleoptionalHeadline; falls back to slug. Clipped from {{schema:@Movie:name}}.
urlrequired for µf2The watched URL (Letterboxd film page) → emitted as u-watch-of. Not the post's own URL — this is the external film-page link.
myUrloptionalThe author's own Letterboxd diary entry for the film. Authored but not currently rendered in any template.
directorrecommendedArray. Clipped from the twitter:data1 meta tag on the Letterboxd page.
yearrecommendedRelease year of the film, as a number. Clipped from {{schema:releasedEvent[*].startDate|date:"YYYY"}}.
genreoptionalArray of genre strings. Clipped from {{schema:genre}}. Some samples use wikilinks ([[Western]]), some plain strings — minor inconsistency between clips.
scoreLBoptionalLetterboxd aggregate rating. Clipped from {{schema:aggregateRating.ratingValue}}. (Also appears as rating in the 3:10 to Yuma sample — drift between clips; see note.)
scoreMyoptionalAuthor's personal rating. Not yet rendered in any template. (Also appears as myRating in the 3:10 to Yuma sample — same drift.)
castoptionalArray of up to 5 cast names. Clipped from {{schema:actors[*].name|slice:0,5}}. Not rendered in templates.
coveroptionalPoster image URL. Clipped from {{schema:image}}. Holds the remote Letterboxd CDN URL at clip time; the Eleventy Image HTML Transform fetches and self-hosts it at build — no co-location step. See build-time cover images.
plotoptionalFilm synopsis. Clipped from the page's description meta tag. Not rendered in templates (contrast with description, which is rendered in the card).
descriptionrecommendedShort hand-written summary. Rendered in the card and feed. Distinct from plot.
daterequiredPost timestamp (sort + dt-published).
draftoptionalAll clipped posts land as draft: true; set to false (or remove) to publish.

Field drift between samples. The two live samples show minor inconsistency: Birth.md uses scoreLB / scoreMy; 310 to Yuma.md uses rating / myRating / scoreLB (both!). This reflects the clipper template being iterated on during early clipping — the clipper template (§13) emits scoreLB and scoreMy as the canonical names going forward. Existing samples are not migrated.

The url field is the Letterboxd film-page URL, not the post's own URL. Eleventy's page.url is always the post's own URL; the frontmatter url field is a separate, author-set field pointing at the external Letterboxd page. The layout emits it as u-watch-of (§5).

5. Microformats (µf2)

Emitted by src/_layouts/watching.njk. The watch target is a hidden <data> element:

{% if url %}<data hidden class="u-watch-of" value="{{ url }}"></data>{% endif %}

<div class="e-content">{{ content | safe }}</div>
PropertyClassFrom
Watch targetu-watch-ofurl (frontmatter field — the Letterboxd film page)
Bodye-contentpost content (the reaction text)
Publisheddt-publisheddate (via entry-header → date.njk)
Authorshiph-entry / h-card / u-authorhidden block, meta.author

h-entry nesting caveat: the only h-entry in the layout is the hidden authorship block; the visible u-watch-of + .e-content sit outside it, so a strict parser won't tie them to the entry. Accepted for v1 (webmention sending isn't wired up). Slated for the webmention milestone.

The url field, not page.url. The layout guards on {% if url %} — this refers to the frontmatter url field (the Letterboxd film-page link), not Eleventy's page.url. In Nunjucks within a layout, bare url resolves to the frontmatter value; page.url is always the post's own URL.

6. Card

Watching has a bespoke poster-led card: src/_includes/partials/card-watching.njk (set in watching.njk: cardPartial = "card-watching.njk"). Built in commit d9dd086, it replaced the shared card-blog.njk precisely so the poster could render: the cover is a plain <img> from cover, which the Eleventy Image transform self-hosts — the shared card reads item.data.image, which Watching posts don't set.

SlotContent
imageitem.data.cover (poster), only if set, rendered as <img eleventy:optional="placeholder" src="{{ item.data.cover | safe }}"> in a slot="image" wrapper — the build-time cover pattern, never the {% image %} shortcode
headlinetitle, linked to the post; sized text-step-1
datedate + a "draft" badge when draft: true
tageach tag except posts; shown only when showTags and more than one tag
contentdescription via markdownFormat
footercategory ("watching")

Renders a <custom-card clickable data-poster> WebC component; the data-poster variant holds a 2/3 poster aspect ratio (custom-card[data-poster] img in css/custom-card.css).

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (watching.xml.njk → feeds/atom-body.njk) and JSON Feed (watching.json.njk → feeds/json-body.njk):

# watching.xml.njk
permalink: /watching/feed.xml
feedCollection = collections.watching
feedTitle = "Watching"
feedDescription = "Films and shows I've watched."
feedSelfUrl = "/watching/feed.xml"
→ includes feeds/atom-body.njk

# watching.json.njk — same vars, with:
permalink: /watching/feed.json
feedSelfUrl = "/watching/feed.json"
→ includes feeds/json-body.njk

The permalink: frontmatter (not the filename) controls the output path.

12. Collection registration (wiring)

// src/_config/collections.js
const byCategory = cat => collection =>
  collection.getFilteredByGlob('./src/posts/**/*.md')
    .filter(item => item.data.category === cat)
    .reverse();
export const watching = byCategory('watching');

// eleventy.config.js
import { ... watching ... } from './src/_config/collections.js';
eleventyConfig.addLayoutAlias('watching', 'watching.njk');
eleventyConfig.addCollection('watching', watching);

Category names never enter tags, so "watching" does not pollute /tags/.

13. Authoring — Web Clipper (Letterboxd — shipped)

The authoring path for a Watching post is "open a Letterboxd film page → trigger the Web Clipper → save to the vault." The Obsidian Web Clipper (browser extension) reads the Letterboxd page's Movie-type JSON-LD through the Letterboxd template and writes a shape-correct .md into src/posts/watching/. This is the one working, shipped clipper template in the JEDEE project — it is the precedent on which the planned Bandcamp template (Jam §14) is modeled.

The template lives at _resources/letterboxd-clipper.json (note: _resources/ at the repo root, not inside src/).

Letterboxd Clipper template (full)

{
  "schemaVersion": "0.1.0",
  "name": "Letterboxd",
  "behavior": "create",
  "noteContentFormat": "",
  "properties": [
    { "name": "title",    "value": "{{schema:@Movie:name}}",                           "type": "text" },
    { "name": "draft",    "value": "true",                                             "type": "checkbox" },
    { "name": "date",     "value": "{{date}}",                                         "type": "text" },
    { "name": "genre",    "value": "{{schema:genre}}",                                 "type": "multitext" },
    { "name": "url",      "value": "{{url}}",                                          "type": "text" },
    { "name": "myUrl",    "value": "",                                                 "type": "text" },
    { "name": "director", "value": "{{meta:name:twitter:data1}}",                      "type": "multitext" },
    { "name": "scoreLB",  "value": "{{schema:aggregateRating.ratingValue}}",           "type": "number" },
    { "name": "scoreMy",  "value": "",                                                 "type": "number" },
    { "name": "cast",     "value": "{{schema:actors[*].name|slice:0,5}}",              "type": "multitext" },
    { "name": "cover",    "value": "{{schema:image}}",                                 "type": "text" },
    { "name": "plot",     "value": "{{description}}",                                  "type": "text" },
    { "name": "year",     "value": "{{schema:releasedEvent[*].startDate|date:\"YYYY\"}}","type": "number" }
  ],
  "triggers": [
    "https://letterboxd.com/film/"
  ],
  "noteNameFormat": "{{schema:@Movie:name}}",
  "path": "posts/watching/"
}

Template metadata

KeyValueNotes
schemaVersion"0.1.0"Obsidian Web Clipper schema version.
behavior"create"Always creates a new note; never overwrites.
noteContentFormat"" (empty)No body template — the note body is left blank for the author to fill in (the reaction text).
triggers["https://letterboxd.com/film/"]Activates only on Letterboxd film-detail pages (not diary, list, or profile pages).
noteNameFormat{{schema:@Movie:name}}Note filename = film title (from JSON-LD). Eleventy slugifies it for the URL (§3).
path"posts/watching/"Flat drop — each clip is a flat .md directly in posts/watching/, not a bundle folder. (Contrast with Jam's planned bundled path.)

Field → Clipper-source mapping

Letterboxd film pages expose a @type: "Movie" JSON-LD block (with embedded aggregateRating, actors[], releasedEvent[], and image) plus standard description and Twitter Card meta tags. The clipper reads from these sources:

FieldClipper sourceSource typeNotes
title{{schema:@Movie:name}}JSON-LD Movie.nameFilm title.
draft"true" (static)—All clips land as drafts; author publishes after writing the reaction body.
date{{date}}Clipper built-inClip timestamp — becomes the post date and dt-published.
genre{{schema:genre}}JSON-LD Movie.genreArray of genre strings.
url{{url}}Clipper built-inThe Letterboxd film-page URL (e.g. https://letterboxd.com/film/birth-2004/). This is not the film's own website; it's the Letterboxd page. Emitted as u-watch-of (§5).
myUrl"" (empty)—Left blank at clip time for the author to paste their own Letterboxd diary entry URL.
director{{meta:name:twitter:data1}}Twitter Card metaLetterboxd puts the director name(s) in the twitter:data1 meta attribute — not in JSON-LD, so this uses the meta selector rather than schema.
scoreLB{{schema:aggregateRating.ratingValue}}JSON-LD Movie.aggregateRatingLetterboxd community rating (e.g. 3.71).
scoreMy"" (empty)—Author's personal rating — left blank at clip time, filled in manually. Not yet rendered in templates.
cast{{schema:actors[*].name|slice:0,5}}JSON-LD Movie.actors[]Up to 5 cast members by name. Not yet rendered in templates.
cover{{schema:image}}JSON-LD Movie.imagePoster image URL on the Letterboxd CDN. Holds the remote URL at clip time; the build-time HTML Transform self-hosts it and the card renders it (§6; cover convention).
plot{{description}}Page <meta name="description">Film synopsis from the Letterboxd page description meta tag. Not rendered in templates — distinct from the hand-written description field.
year{{schema:releasedEvent[*].startDate|date:"YYYY"}}JSON-LD Movie.releasedEvent[].startDateRelease year (four-digit number).

Fields not emitted by the template. category, layout, and permalink come from the folder data file src/posts/watching/watching.json (§1, §12), not per-post, so the template omits them. The description field (the short hand-written summary that appears in the card) is not emitted by the clipper — it is written by the author after clipping. The noteContentFormat is empty, so the note body is also blank at clip time.

Flat path — and that's the design. The Letterboxd clipper writes flat .md files directly into posts/watching/, and the cover field holds a remote URL. That is now the intended end state, not a stopgap: the Eleventy Image HTML Transform fetches and self-hosts the remote poster at build (cover convention), so no co-location step is needed. The earlier idea of a normalize/download script to bring the poster local was dropped (23 May 2026) as redundant. Covers stay flat across reading / watching / jam.

The url field is the Letterboxd film-page URL — not the film's own website. Letterboxd pages do not expose the film's canonical URL (IMDB, official site, etc.) in the JSON-LD; the clipper captures the page URL itself. This Letterboxd URL is what becomes u-watch-of, which is semantically appropriate: the IndieWeb watch-of property points to where you watched/logged the content, not the film's canonical home.

14. Webmentions

Webmention is the IndieWeb's federated response protocol: likes, replies, and reposts from other sites arrive as cross-site comments. Nothing here is Watching-specific — the plumbing is shared by every post type and Watching inherits it through the base layout and entry-footer.njk. Discovery is shipped; receiving and sending are deferred to the webmention milestone.

PieceStateWhere
Endpoint discoveryshipped (Phase 1)<link rel="webmention" href="https://webmention.io/johanedlund.se/webmention"> in <head> via src/_includes/head/meta-info.njk (watching uses layout: base).
Authorship h-cardshippedThe hidden h-entry block in watching.njk carries u-url, p-name u-url rel="author", and a u-author h-card avatar so a receiver can attribute the post (§5).
Render slotwired, no-opwatching.njk → entry-footer.njk → partials/webmentions.njk, currently an empty stub — safe to call while the renderer is empty.
Receiving / renderingdeferredThe webmention milestone wires a webmention.io fetch (via @11ty/eleventy-fetch, ~24 h cache); webmentions.njk then groups received mentions by type (likes / replies / reposts / mentions).
SendingdeferredOutgoing webmentions aren't wired, so a Watching post that responds to another post doesn't notify it yet.

h-entry nesting (§5). The only h-entry in the layout is the hidden authorship block; the visible u-watch-of + .e-content sit outside it, so a strict parser won't tie the watch target to the entry. Harmless while sending is off; fix it when the sending side of the milestone lands — see §5.

15. Status & open items

  • Shipped in Phase 2 — layout, archive, feed, nav, and 2 sample posts all live. The Letterboxd Web Clipper template is the one shipped clipper in the project.
  • cover vs. image mismatch — RESOLVED (option c, commit d9dd086). The bespoke card-watching.njk reads cover directly and renders it as a plain <img> the build-time transform self-hosts (§6) — no aliasing or fallback needed.
  • myUrl, scoreMy, cast, plot — authored but not rendered in any template. Surfaces for a richer per-post layout. (open)
  • Field drift between samples — scoreLB/rating and scoreMy/myRating inconsistency between the two live samples (see §4 note). The clipper template emits the canonical names (scoreLB, scoreMy); existing samples are not migrated. (open)
  • Webmentions — discovery + the no-op render slot are shipped; receiving/rendering, sending, and the h-entry nesting fix (§5) are deferred to the webmention milestone. See §14.
  • Schema upgrade BlogPosting → WatchAction — Phase 4.
  • Cover co-location — NOT planned (dropped). The clipper writes a flat .md with a remote cover: URL, and that is the locked design: the build-time HTML Transform self-hosts the poster (cover convention). The earlier normalize/download step was dropped 23 May 2026 as redundant. Covers stay flat.
  • Dedicated card — DONE (commit d9dd086). card-watching.njk is the poster-led card (§6). Surfacing more fields on it — year, director, rating — remains a candidate enhancement. (open: richer card face)
  • Micropub endpoint — forward-compat only; nothing Watching-specific to add beyond the shared plumbing. Sequenced after Phase 4. (open)
