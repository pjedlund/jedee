post-type spec

Article

Shipped · Phase 2 · singular article / plural articles · generic post layout · extracted from live code 22 May 2026

An Article is a long-form blog post — the canonical, open-ended writing type on JEDEE. It is the original post type inherited from the Eleventy Excellent starter and serves as the default model all other types extend or diverge from. It carries no syndication verb (no "read of", "watch of", etc.): it is simply something the author wrote.

1. Singular / plural identity

Article is asymmetric in a way that is more pronounced than any other type: the folder, URL, archive, and feed are all plural, but the category, collection, and layout alias are all singular — and the layout itself is the generic post.njk, not a dedicated article.njk. This layout reuse is the defining trait of the type: Article has no custom per-post layout of its own.

Note the mismatch: the folder is articles/ but its data file sets category: "article", and the collection registered from that category is article (singular). The layout alias is also singular (post), but the alias itself is generic — shared with nothing today, but not article-specific. Don't "fix" this — the asymmetry is by design and mirrors every other post type's singular/plural split.

2. Naming & aliases

JEDEE's long-form writing type is called Article (singular) / Articles (plural). It is the original Eleventy Excellent post type and the conceptual default — the type every other post type either extends or deliberately differs from.

TermStatusWhere it appears / why
article / articleschosen nameType, layout alias, collection, URL, archive, feed, nav (see §1).
postlayout aliasThe post alias maps to post.njk in eleventy.config.js. Article is the only type that uses this generic layout directly; all other shipped types have their own layout file (jam.njk, note.njk, etc.).
BlogPostingSchema.org typeSet in post.njk front matter (schema: BlogPosting) and rendered by src/_includes/schemas/BlogPosting.njk (see §10).

3. URLs & permalinks

PageURLSource
Per-post/articles/<slug>/"/articles/{{ title | slugify }}/index.html"
Archive (page 1)/articles/articles.njk pagination, size 8
Archive (page N)/articles/page-N/same
Atom feed/articles/feed.xmlarticles.xml.njk
JSON feed/articles/feed.jsonarticles.json.njk

Slug derives from the title field via | slugify — not from the filename. This means articles.json sets permalink: "/articles/{{ title | slugify }}/index.html". A post titled "Design token naming conventions: what the standard actually says" yields /articles/design-token-naming-conventions-what-the-standard-actually-says/. The filename (e.g. 2026-04-24-design-token-naming-conventions.md) is used only for sorting within the year subfolder and is not surfaced in the URL.

Title-required consequence: because the permalink is derived from title, every Article post must have a title field. A missing or empty title produces an empty slug and a broken permalink. This differs from title-optional types (e.g. Jam) where the filename drives the URL.

titlerequiredHeadline; also drives the permalink slug via | slugify (see §3). Must be present.
daterequiredPost timestamp (sort + dt-published).
descriptionrecommendedCard excerpt, feed summary, and meta description / OG description via the base layout.
draftoptionalWhen true, shows a "draft" badge in the card and entry header. The post still builds unless also excluded from collections (see note below).
tagsoptionalTopic tags (e.g. design-systems, css). Not the category. Tags appear on the card, in entry-footer.njk, and on the /tags/ index.
imageoptionalFeature image; rendered by entry-header.njk (full-width "feature" class) and the card.
altoptionalAlt text for image; passed to entry-header.njk.
creditoptionalImage credit line; passed to entry-header.njk.
bgColoroptionalSeen in live samples but not currently rendered by the post layout — carried through as data only.
updatedDateoptionalRenders "| Updated: …" in entry-header.njk.
eleventyExcludeFromCollectionsoptionalWhen true, excludes the post from all Eleventy collections (so it won't appear in the archive or feed). Both live samples use this alongside draft: true.
excludeFromSitemapoptionalKeeps the post out of sitemap.xml.

draft vs. exclude: draft: true is a display flag only — it shows the badge but does not remove the post from collections. To hide a draft from the archive and feed, also set eleventyExcludeFromCollections: true. Both live samples set all three fields. An Article intended for public review (e.g. a staged post) could carry draft: true without the exclude flags.

5. Microformats (µf2)

Emitted by src/_layouts/post.njk. Article is a plain author post — it carries no syndication verb (u-read-of, u-listen-of, u-watch-of). The µf2 surface is minimal:

<div class="e-content">
  {{ content | safe }}
</div>
PropertyClassFrom
Bodye-contentpost content
Publisheddt-publisheddate (via entry-header.njk → date.njk)
Authorshiph-entry / h-card / u-authorhidden block, meta.author

No backlinks partial. post.njk does not include partials/backlinks.njk. The note, reading, watching, and jam layouts do. This is deliberate — Articles are the author's own writing and don't need a "responding to" target display.

h-entry nesting caveat: the only h-entry in the layout is the hidden authorship block; the visible .e-content sits outside it, so a strict µf2 parser won't tie the body to the entry. Accepted for v1; slated for the webmention milestone.

7. Archive page config

src/pages/articles.njk drives the listing through the shared archive-listing.njk partial:

pagination: { data: collections.article, size: 8 }
permalink:  articles/[page-N/]index.html
cardPartial = "card-blog.njk"
masonryLayout = "thirds"
collectionToPaginate = collections.article
paginationMetaKey = "blog"

Pagination size is 8 (larger than Jam's 3), and the masonry layout is thirds (three columns), not "50-50".

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (articles.xml.njk → feeds/atom-body.njk) and JSON Feed (articles.json.njk → feeds/json-body.njk):

# articles.xml.njk
permalink: /articles/feed.xml
feedCollection = collections.article
feedTitle = "Articles"
feedDescription = "Long-form posts."
feedSelfUrl = "/articles/feed.xml"
→ includes feeds/atom-body.njk

# articles.json.njk — same vars, with:
permalink: /articles/feed.json
feedSelfUrl = "/articles/feed.json"
→ includes feeds/json-body.njk

The permalink: frontmatter (not the filename) controls the output path. Both feed templates also carry eleventyExcludeFromCollections: true and excludeFromSitemap: true.

Year subfolders. Article posts are organized into per-year subdirectories (2022/ … 2026/) inside src/posts/articles/. No other shipped type does this — Jam, Note, Reading, and Watching use flat posts/<type>/ folders. The subfolder structure is for human organization only; Eleventy's glob (./src/posts/**/*.md) traverses it transparently. The year prefix in filenames (e.g. 2026-04-24-…) is a naming convention, not a structural requirement.

Page bundles in the wild. Two 2025 entries (2025-01-09-post-with-image/ and 2025-06-05-my blog post with pheasant/) already exist as bundle folders. This is co-located Eleventy Image support — a folder containing the post markdown and its images. There is no formal bundle migration plan for Articles (unlike Jam's §12); these bundles exist ad hoc.

12. Collection registration (wiring)

// src/_config/collections.js
const byCategory = cat => collection =>
  collection.getFilteredByGlob('./src/posts/**/*.md')
    .filter(item => item.data.category === cat)
    .reverse();
export const article = byCategory('article');

// eleventy.config.js
import { ... article ... } from './src/_config/collections.js';
eleventyConfig.addLayoutAlias('post', 'post.njk');
eleventyConfig.addCollection('article', article);

Category names never enter tags, so "article" does not pollute /tags/. The tags: "posts" string in articles.json feeds the Eleventy built-in firehose collection (collections.posts) and is separate from the per-type collections.article registered above.

13. Webmentions

Webmention is the IndieWeb's federated response protocol: likes, replies, and reposts from other sites arrive as cross-site comments. Nothing here is Article-specific — the plumbing is shared by every post type and Article inherits it through the base layout and entry-footer.njk. Discovery is shipped; receiving and sending are deferred to the webmention milestone.

PieceStateWhere
Endpoint discoveryshipped (Phase 1)<link rel="webmention" href="https://webmention.io/johanedlund.se/webmention"> in <head> via src/_includes/head/meta-info.njk (article uses layout: base via post.njk).
Authorship h-cardshippedThe hidden h-entry block in post.njk carries u-url, p-name u-url rel="author", and a u-author h-card avatar so a receiver can attribute the post (§5).
Render slotwired, no-oppost.njk → entry-footer.njk → partials/webmentions.njk, currently an empty stub — safe to call while the renderer is empty.
Receiving / renderingdeferredThe webmention milestone wires a webmention.io fetch (via @11ty/eleventy-fetch, ~24 h cache); webmentions.njk then groups received mentions by type (likes / replies / reposts / mentions).
SendingdeferredOutgoing webmentions aren't wired, so an Article that links to another post doesn't notify it yet.

h-entry nesting (§5). The only h-entry in the layout is the hidden authorship block; the visible .e-content sits outside it, so a strict parser won't tie the body content to the entry. Harmless while sending is off; fix it when the sending side of the milestone lands.

14. Status & open items

  • Shipped as the original Eleventy Excellent post type — layout, archive, feed, nav, and multiple sample posts all live. Year subfolders and the generic post layout predate the other types.
  • Title-required permalink — the slug derives from title | slugify (not the filename). A missing title breaks the permalink silently. No enforcement mechanism exists today. (open)
  • Webmentions — discovery + the no-op render slot are shipped; receiving/rendering, sending, and the h-entry nesting fix (§5) are deferred to the webmention milestone. See §13.
  • Schema — BlogPosting is the permanent target type for Article (no planned upgrade). It is the most accurate Schema.org type for long-form author writing.
  • Page bundles — two 2025 posts already exist as ad-hoc page bundles (folder + co-located images). No formal migration plan; the post.njk layout supports co-located images via the Eleventy Image HTML Transform. (no open action)
  • Micropub — no endpoint today; deferred to a post-Phase-4 milestone. Article's BlogPosting shape is a natural Micropub create target (h-entry without a syndication verb), so no frontmatter retrofit is expected.
  • Web Clipper — no Clipper template planned for Articles (Articles are authored, not clipped from external sources).
  • bgColor field — present in a live sample (2025-01-11-v-4.md) but not rendered by post.njk or the card. Carried as data only; no design is settled. (open)
