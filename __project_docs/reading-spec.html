post-type spec

Reading

Shipped · Phase 2 · uniform singular reading · extracted from live code 22 May 2026

A Reading is a post sharing a book the author is reading or has read — title, author, cover art, and a brief description or response. An IndieWeb "read" post.

1. Singular / plural identity

Reading is symmetric singular: every aspect — the type, the folder, the URL, the archive, the collection, the feed — uses the same word reading. This is a deliberate contrast with Jam, which is asymmetric (singular type, plural URL namespace). Reading has no such mismatch: the folder is reading/, the URL is /reading/, and the collection is collections.reading — all singular, all the same.

Contrast with Jam: Jam uses a plural folder (src/posts/jams/), plural URL (/jams/), and plural archive (jams.njk) while the type, layout, and collection are singular (jam). Reading has no such split — every token is reading (singular). Don't "fix" either: both are intentional.

2. Naming & aliases

The type is named Reading — a gerund form that describes an ongoing or completed act of reading, not a list of titles. It maps cleanly to IndieWeb's read post type.

TermStatusWhere it appears / why
readingchosen nameType, layout, collection, folder, URL, archive, feed, nav (see §1). Uniform singular.
readIndieWeb verb — kept in µf2There is no "reading" microformat: the property is u-read-of. The layout emits it from the link field (see §5).

3. URLs & permalinks

PageURLSource
Per-post/reading/<slug>/"/reading/{{ page.fileSlug | slugify }}/index.html"
Archive (page 1)/reading/reading.njk pagination, size 2
Archive (page N)/reading/page-N/same
Atom feed/reading/feed.xmlreading.xml.njk
JSON feed/reading/feed.jsonreading.json.njk

Slug derives from the .md filename via page.fileSlug | slugify — the folder data file sets permalink: "/reading/{{ page.fileSlug | slugify }}/index.html". Filename Anna Karenina - Leo Tolstoy.md → /reading/anna-karenina-leo-tolstoy/. For a page-bundle post the slug still comes from the .md filename (not the folder name) — and here the two diverge (folder Drottningar i Kungahalla/ vs file Drottningar i Kungahälla - Selma Lagerlöf.md), so the URL is derived from the file (see §12).

The archive pagination size is 2 per page (not 3 like Jam). Pagination is only rendered when the collection has more items than the page size.

Importer field sprawl: the Google Books importer emits author, authors, subtitle, previewLink, isbn13, isbn10, and totalPage — several of which are redundant or unrendered. These are accepted as-is; no migration planned. The canonical forward shape will be tightened when a Goodreads/StoryGraph web clipper template is authored (see §15).

Cover field: the current flat posts use remote coverUrl / coverSmallUrl paths. The page-bundle pattern (already in use — see §12) enables co-located covers in the future.

h-entry nesting caveat: the only h-entry in the layout is the hidden authorship block; the visible u-read-of + .e-content sit outside it, so a strict parser won't tie them to the entry. Accepted for v1 (webmention sending isn't wired up). Slated for the webmention milestone.

6. Card

Reading has a bespoke card: src/_includes/partials/card-reading.njk. It is set in reading.njk via cardPartial = "card-reading.njk". Unlike the shared card-blog.njk used by Jams, this card is book-cover-led: it omits the post date and draft badge from the card face, and filters out the reading tag from the tag list.

SlotContent
headlinetitle, linked to the post; sized text-step-2
tageach tag except "reading"; shown only when showTags is true and there is more than one tag
contentdescription passed through markdownFormat
footercategory ("reading")

Renders a <custom-card clickable> WebC component (no img-square or no-padding modifiers). The date/draft badge slot is commented out in the current source. Styles via css/custom-card.css.

No cover rendered on the card: the bespoke card does not currently display coverUrl or coverSmallUrl as an image. The card is headline- and description-led. A future iteration could add cover art as the primary visual (as the Jam spec notes card-reading.njk as the model for a potential album-art-led card-jams.njk).

7. Archive page config

src/pages/reading.njk drives the listing through the shared archive-listing.njk partial:

pagination: { data: collections.reading, size: 2 }
permalink:  reading/[page-N/]index.html
cardPartial = "card-reading.njk"
masonryLayout = "50-50"
collectionToPaginate = collections.reading
paginationMetaKey = "blog"

The archive description is set inline in reading.njk and mentions the pagination size and current collection length dynamically.

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (reading.xml.njk → feeds/atom-body.njk) and JSON Feed (reading.json.njk → feeds/json-body.njk):

# reading.xml.njk
permalink: /reading/feed.xml
feedCollection = collections.reading
feedTitle = "Reading"
feedDescription = "Books I'm reading."
feedSelfUrl = "/reading/feed.xml"
→ includes feeds/atom-body.njk

# reading.json.njk — same vars, with:
permalink: /reading/feed.json
feedSelfUrl = "/reading/feed.json"
→ includes feeds/json-body.njk

Both feed files also set eleventyExcludeFromCollections: true and excludeFromSitemap: true. The permalink: frontmatter (not the filename) controls the output path.

12. Page bundle / co-located assets

Unlike Jam — where page bundles are planned — Reading already uses the bundle pattern in production. The post Drottningar i Kungahälla is a page-bundle folder, not a flat .md:

src/posts/reading/
└── Drottningar i Kungahalla/                    # folder named for the post
    └── Drottningar i Kungahälla - Selma Lagerlöf.md   # the post file, same name

Eleventy Excellent's convention is a directory named for the post containing a single .md — ideally with the same name as the folder (a tidy convention; the slug itself always comes from the filename via page.fileSlug, which only coincides with the folder name when they match). This post deviates: the folder is Drottningar i Kungahalla but the file is Drottningar i Kungahälla - Selma Lagerlöf.md, so the slug is taken from the filename. The data file, layout, and permalink are inherited from reading.json either way. Any co-located assets — images, attachments — placed alongside the .md are passthrough-copied by Eleventy and served relative to the post's URL.

AspectFlat post (current majority)Bundle post (Drottningar — shipped)
Post filesrc/posts/reading/<title>.mdsrc/posts/reading/<folder>/<title>.md
Co-located assetsnone (covers stored remotely or in /assets/images/reading/)any file placed next to the .md in the bundle folder
Slug sourcepage.fileSlug (filename) via | slugifypage.fileSlug (the .md filename) via | slugify — not the folder, since this bundle's folder and file names differ

The Drottningar bundle currently contains only the .md file — no co-located image yet. But the structure is live and correct; adding a cover.jpg alongside the .md would make it available relative to the post's URL (the exact slug being filename-derived, as above). The coverUrl field in this post still points to a remote Google Books URL, same as the flat posts.

13. Collection registration (wiring)

// src/_config/collections.js
const byCategory = cat => collection =>
  collection.getFilteredByGlob('./src/posts/**/*.md')
    .filter(item => item.data.category === cat)
    .reverse();
export const reading = byCategory('reading');

// eleventy.config.js
import { ... reading ... } from './src/_config/collections.js';
eleventyConfig.addLayoutAlias('reading', 'reading.njk');
eleventyConfig.addCollection('reading', reading);

Category names never enter tags, so "reading" does not pollute /tags/. The folder data file sets tags: "posts" (the system tag that puts items in the global posts collection), not category.

14. Webmentions

Webmention is the IndieWeb's federated response protocol: likes, replies, and reposts from other sites arrive as cross-site comments. Nothing here is Reading-specific — the plumbing is shared by every post type and Reading inherits it through the base layout and entry-footer.njk. Discovery is shipped; receiving and sending are deferred to the webmention milestone.

PieceStateWhere
Endpoint discoveryshipped (Phase 1)<link rel="webmention" href="https://webmention.io/johanedlund.se/webmention"> in <head> via src/_includes/head/meta-info.njk (reading uses layout: base).
Authorship h-cardshippedThe hidden h-entry block in reading.njk carries u-url, p-name u-url rel="author", and a u-author h-card avatar so a receiver can attribute the post (§5).
Render slotwired, no-opreading.njk → entry-footer.njk → partials/webmentions.njk, currently an empty stub — safe to call while the renderer is empty.
Receiving / renderingdeferredThe webmention milestone wires a webmention.io fetch (via @11ty/eleventy-fetch, ~24 h cache); webmentions.njk then groups received mentions by type (likes / replies / reposts / mentions).
SendingdeferredOutgoing webmentions aren't wired, so a Reading post that responds to another post doesn't notify it yet.

h-entry nesting (§5). The only h-entry in the layout is the hidden authorship block; the visible u-read-of + .e-content sit outside it, so a strict parser won't tie the read target to the entry. Harmless while sending is off; fix it when the sending side of the milestone lands.

15. Status & open items

  • Shipped — layout, archive, feed, nav, and sample posts all live. Page bundles in use (§12).
  • Bespoke card — card-reading.njk is shipped; the cover image (coverUrl) is not rendered on the card face. Adding cover-art display is a candidate enhancement. (open)
  • Field sprawl — the Google Books importer emits many fields (authors, subtitle, previewLink, isbn13, isbn10, totalPage) that are not currently rendered. No cleanup planned until a web clipper template is built. (open)
  • Cover fields — current posts use remote coverUrl / coverSmallUrl URLs, not co-located assets. The bundle pattern (§12) is already in use structurally; co-locating covers is the next step. (open)
  • Authoring (Web Clipper) — no Goodreads / StoryGraph web clipper template exists yet. Authoring is currently manual or via a Google Books importer script. (open)
  • Micropub — no endpoint today; the Reading type is shaped as an IndieWeb read post (u-read-of), which is the canonical Micropub property for read posts. Forward-compat only; endpoint is a separate milestone after Phase 4.
  • Webmentions — discovery + the no-op render slot are shipped; receiving/rendering, sending, and the h-entry nesting fix (§5) are deferred to the webmention milestone. See §14.
  • Schema upgrade — BlogPosting → ReadAction (embedding a Book object) is planned for Phase 4. Fields like isbn13, author, and publisher are already in frontmatter and ready to map.
  • Unrendered metadata — publisher, publishDate, totalPage, isbn13, isbn10, previewLink are authored but not surfaced in any template. Candidate for a book-metadata aside or schema enrichment. (open)
