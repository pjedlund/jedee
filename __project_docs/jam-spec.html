post-type spec

Jam

Shipped · Phase 2 · singular jam / plural jams · extracted from live code 22 May 2026 · reconciled 15 Jun 2026 (one consistent field shape; both clippers + the Micropub endpoint now built & live)

A Jam is a short post sharing music (or other audio) the author is listening to — an album, track, or release, usually linking out to Bandcamp or a streaming service. An IndieWeb "listen" post.

1. Singular / plural identity

Jam is asymmetric: the type is singular, the URL namespace is plural. The Eleventy collection is named with the singular (collections.jam), but the folder, URL, archive, and feed all use the plural.

Note the mismatch: the folder is jams/ but its data file sets category: "jam", and the collection registered from that category is jam (singular). Don't "fix" this — the layout alias, collection, and category are all singular by design.

2. Naming & aliases

JEDEE's music type is named Jam (singular) / Jams (plural), after This Is My Jam — a curated endorsement, not a passive scrobble of whatever happened to be playing. Chosen deliberately over symmetry with reading / watching because the word carries the endorsement.

TermStatusWhere it appears / why
jam / jamschosen nameType, layout, collection, URL, archive, feed, nav (see §1).
listenIndieWeb verb — kept in µf2 + schemaThere is no "jam" microformat: the property is u-listen-of and the planned schema is ListenAction. Jam reuses IndieWeb's listen vocabulary.
listeningprevious name + asset pathThe folder was src/posts/listening/ until Phase 2 renamed it to jams/. The earlier /listening/* /jams/:splat 301 redirect has been removed, freeing the /listening/ namespace for a possible future Listen type (see note). Album art still lives under /assets/images/listening/.
thisismyjamtopic tag (imports only)The 114 This Is My Jam imports carry tags: [posts, thisismyjam]; new/clipped jams carry only the inherited posts tag. There is no music tag (the earlier samples' tags: [music] are gone — those samples were removed). User tags only, never the category.

Listen vs. Jam: IndieWeb splits Listen (passive scrobbles — whatever's playing) from Jam (curated picks). If a scrobble feed ever lands it would be a separate Listen type at /listening/, not a rename of Jam.

4. Frontmatter

This is the one consistent shape — identical whether a jam is hand-written, clipped (Apple Music / Bandcamp), or posted by Micropub. The drift the original spec worried about is resolved: the canonical names below are what the live posts, both clippers, and the endpoint all use (Job 2A/2B, 15 Jun 2026). Live sample (src/posts/jams/Chasing The Dream.md):

---
title: Chasing The Dream                              # the song (track jam) or the album (album jam)
draft: false
artist: "[[Woo York]]"                                # performer — [[wikilink]] for the Obsidian graph
album: Chasing The Dream                              # the release
source: https://music.apple.com/se/album/chasing-the-dream/1716473287   # → u-listen-of target
cover: https://is1-ssl.mzstatic.com/.../1200x630bb.jpg                  # album art (remote URL; self-hosted at build)
description: Soft rolling beats with lots of texture.
genre:                                                # one or more — [[wikilinks]]
  - "[[Techno]]"
  - "[[Dance]]"
year: 2018                                            # release year
favoriteTrack: Walking Along The Rainbow              # optional spotlight song
favoriteTrackUrl: https://music.apple.com/se/song/walk-along-the-rainbow/1716473667
odesliUrl: https://album.link/i/1716473287            # optional cross-platform link (data only)
date: 2026-06-11T22:52:34+02:00                       # post date
---
FieldReq?Role
titleoptionalHeadline — the song for a track jam, the album for an album jam. Falls back to slug.
artistrecommendedPerformer, stored as a [[wikilink]] for the Obsidian graph; rendered as plain text (brackets stripped via the unwikilink filter). 117 / 118 jams carry it.
albumrecommendedThe release. Plain text (same value as title on an album jam).
sourcerequired for µf2The listened-to URL (Apple Music / Bandcamp) → emitted as u-listen-of.
coveroptionalAlbum art — a remote URL (or a local /assets/images/listening/ path); rendered as a plain <img> by the card and layout, self-hosted at build (§6, §12; cover convention).
yearoptionalRelease year (a number). Renamed from the original spec's released.
genreoptionalOne or more, stored as a list of [[wikilinks]]; rendered as plain text via unwikilink. A graph value, not site tags.
favoriteTrack + favoriteTrackUrloptionalOptional spotlight song + its link. Pair 1:1 (only 3 jams set them today).
odesliUrloptionalsong.link / album.link cross-platform URL. Data only — kept in front matter, not rendered as a link. Renamed from the original spec's odeslico.
youtubeSlugoptionalA bare YouTube video id (e.g. 6-rWAs7gQpc) embedded via <custom-youtube>. camelCase (a hyphen reads as subtraction in Nunjucks). Renamed from youtube (Job 2B, 15 Jun 2026); 74 jams carry it.
descriptionrecommendedCard excerpt + feed summary.
daterequiredPost timestamp (sort + dt-published).
tags · draftoptionalUser tags (imports carry thisismyjam; §2) · draft flag. Not the category.

Field shape — locked

Canonical names, one shape (Job 2A/2B, 15 Jun 2026). The earlier "canonical vs. live drift" is closed: source (not listen-of), year (not released), odesliUrl (not odeslico/syndication), cover (was image, commit d9dd086), plus youtubeSlug (was youtube). These names are now used identically by the live posts, the two clippers (§14), and the Micropub endpoint (§15) — no per-producer mapping. Covers stay flat (no page bundle, no coverSource: — dropped 23 May 2026; §12). favoriteTrack can't come from Micropub (Sparkles only knows the album), so it simply stays empty on a posted jam.

5. Microformats (µf2)

Emitted by src/_layouts/jam.njk. The article itself is the h-entry root (promoted 6 Jun 2026), so the visible properties sit inside the entry. The listen target is a hidden <data> element (Jams have a visible body, so the target need not be visible):

<article class="wrapper flow prose h-entry">
  {% if youtubeSlug %}<custom-youtube @slug="{{ youtubeSlug }}" @label="{{ title }}"></custom-youtube>{% endif %}
  {% if source %}<data hidden class="u-listen-of" value="{{ source }}"></data>{% endif %}
  <div class="e-content">{{ content | safe }}</div>
</article>
PropertyClassFrom
Listen targetu-listen-ofsource
Bodye-contentpost content
Publisheddt-publisheddate (via entry-header)
Authorshiph-entry / h-card / u-authorhidden block, meta.author

h-entry nesting — resolved (6 Jun 2026). The old caveat (only the hidden authorship block was an h-entry, leaving u-listen-of + .e-content outside it) is fixed: the article is now the h-entry root, so every visible property is tied to the entry. The recovered This Is My Jam likes/comments are deliberately rendered outside that root (partials/jam-social.njk), like received webmentions, so the h-cite cards don't nest as children of the entry.

Visible metadata block — in progress (Job 2C). The front-matter shape (§4) is locked and the data is present on most jams, but the permalink page does not yet render artist / album / year / genre / favoriteTrack as a visible block — that markup + its local CSS bundle is the remaining Job 2C step. The unwikilink filter (built 15 Jun) is ready to strip [[ ]] from artist / genre for display. Until then the page shows title, cover, the optional YouTube embed, the body tracklist, and the social block.

6. Card

Jam has a bespoke album-art-led card: src/_includes/partials/card-jam.njk (set in jams.njk: cardPartial = "card-jam.njk"). Built in commit d9dd086, it replaced the shared card-blog.njk so the album art could render from cover (the shared card reads item.data.image, which Jam no longer sets). It mirrors card-watching.njk.

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (jams.xml.njk → feeds/atom-body.njk) and JSON Feed (jams.json.njk → feeds/json-body.njk):

# jams.xml.njk
permalink: /jams/feed.xml
feedCollection = collections.jam
feedTitle = "Jams"
feedDescription = "Music I'm listening to."
feedSelfUrl = "/jams/feed.xml"
→ includes feeds/atom-body.njk

# jams.json.njk — same vars, with:
permalink: /jams/feed.json
feedSelfUrl = "/jams/feed.json"
→ includes feeds/json-body.njk

The permalink: frontmatter (not the filename) controls the output path.

12. Cover image & page bundles

The album art is handled by the project-wide build-time cover pattern: the cover: field holds a local path or a remote URL, the layout and card render it as a plain <img eleventy:optional="placeholder" src="{{ cover | safe }}">, and the Eleventy Image HTML Transform optimizes (local) or fetches + optimizes (remote) and self-hosts it at build. Jams stay flat .md files with the cover under /assets/images/listening/ (or a remote URL) — no page bundle is needed for the cover.

The page-bundle / co-located-cover plan was dropped (23 May 2026). An earlier Clipper-era plan made each Jam a page bundle holding cover: ./cover.<ext> plus a coverSource: origin field, with a colocate-covers.js / normalize-posts.js script to download remote art into the bundle. That apparatus was never built: the build-time transform already self-hosts the remote cover, so the download-and-commit step was redundant. The coverSource: field and the colocate script do not exist.

AspectWas planned (Clipper-era — dropped)Locked (shipped)
Post filepage bundle src/posts/jams/<slug>/<slug>.mdflat src/posts/jams/<slug>.md
Cover storageco-located cover.<ext> downloaded into the bundleremote URL, or /assets/images/listening/<file>; self-hosted at build
Frontmattercover: ./cover.<ext> + coverSource:single cover: (URL or path)
How it landsa colocate / normalize script downloads + commits the filethe HTML Transform fetches/optimizes at build; nothing committed (dist/ is gitignored)

Page bundles themselves remain available (Eleventy Excellent's <folder>/<folder-name>.md convention) for any genuine co-located body assets a Jam might gain — they're just no longer the mechanism for the cover.

Category names never enter tags, so "jam" does not pollute /tags/.

14. Authoring — Web Clipper + plugin setup

The authoring path for a Jam is "right-click an album page → save to the vault." The Obsidian Web Clipper (browser extension) reads the page's MusicAlbum JSON-LD through a per-source template and writes a shape-correct .md flat into src/posts/jams/. The cover property holds the remote album-art URL, which the build-time HTML Transform self-hosts; nothing is downloaded into the vault (§12). No per-post manual frontmatter typing.

Built & live. Two jam clippers are authored, git-tracked, and verified live: src/_obsidian/clipper/apple-music-clipper.json (live 9 Jun 2026) and bandcamp-clipper.json (live 8 Jun 2026). Both emit the canonical §4 shape. The living per-type detail — selectors, the Bandcamp keywords-vs-genre trap, trigger formats, the manual-fill fields — is in web-clipper-pattern.html and the web-clipper skill; the canonical contract is below.

The Bandcamp clipper is the sibling: same path/shape, a /bandcamp\.com/album/ regex trigger, byArtist.name (a bare object, not an array), genre from keywords (Bandcamp exposes no top-level genre), and a track.itemListElement tracklist body. The body map+template captures the linked tracklist as markdown.

Field → source mapping (canonical)

The clippers emit the canonical shape directly — the same names the live posts and the Micropub endpoint use (§4, §15). No normalize/reconcile step; what the clipper writes is what ships.

FieldClipper source (Apple Music)Notes

artist{{schema:@MusicAlbum:byArtist[0].name|wikilink}}Wikilinked for the graph; rendered plain via unwikilink (§4). Single text (a band name with commas would comma-shatter on multitext).

Not emitted by the template. category, layout, and permalink come from the folder data file src/posts/jams/jams.json (§1, §13), not per-post, so the templates omit them — and so is tags (no music tag; the folder cascade adds posts, §2). The path is the flat posts/jams/ (no bundle), and noteNameFormat is title-only ({{schema:@MusicAlbum:name|safe_name}} — the old ", by <Artist>" form was reversed so [[wikilinks]] resolve); safe_name strips filesystem-illegal characters and Eleventy slugifies for the URL at build (§3).

Obsidian plugin setup

One vault-side community plugin completes the authoring flow:

PluginRoleRequired settings
obsidian-local-images-plus (installed)Downloads body images — markdown ![](URL), <img src>, base64 — into a folder named after the note. Automatic, MD5-named, idempotent. Does not touch YAML frontmatter.Automatic mode on; placement "next to note in a folder named after the note."

Division of labor. The Clipper writes the flat .md (frontmatter plus the linked tracklist as a markdown body). It does not download images — and it no longer needs to: the cover stays a remote URL and the build-time HTML Transform self-hosts it at build (§12). The dropped normalize / colocate step is therefore unnecessary — there is no per-clip cover download and no backfill. Demoting the cover into the body to let a plugin grab it was rejected — covers are data for cards / OG / JSON-LD, not body content. obsidian-local-images-plus still handles a genuine body image (e.g. an inline album-art <img> inside a clip), but is a no-op for the typical Jam clip.

15. Micropub — built & live

JEDEE has a live Micropub endpoint — netlify/functions/micropub.js, mounted at /api/micropub — built, merged, and verified end-to-end (31 May 2026). It is a single Netlify Function on the vendor-but-patch engine @benjifs/micropub + @benjifs/github-store with hosted IndieAuth; it turns an incoming h-entry into a shape-correct .md committed to the repo. A Micropub create for a Jam is a listen post (Sparkles' Listen editor). The full design + the three patch points live in micropub-pattern.html and the micropub skill; the jam-specific routing is below.

StepHow a posted jam lands as the §4 shapeSee
Routing → folderThe engine routes listen-of → posts/jams/; category: "jam" then falls out of the folder's data cascade (never written per-post).§1, §13
Identity keyThe cite's url becomes source (→ u-listen-of) — the same canonical key the clippers emit.§5, §14
Listen-only cite shape (Job 2B, 15 Jun 2026)Sparkles nests the album in an h-cite. The endpoint destructures it for a jam as: name → title and name → album; author → artist (not author); photo → cover; published → year. Watch/read keep author and never get artist/album.§4, §14
CoverWritten as a cover: URL (a thumbnail is upgraded to full-res), self-hosted at build — no download, no coverSource:.§12

One shape, three producers. The frontmatter a hand-written jam, a clip (§14), and a Micropub post carry is the same shape — no per-producer field mapping. The one gap: favoriteTrack can't come from Micropub (Sparkles only knows the album), so a posted jam simply leaves it empty (it's optional). Covers self-hosted + flat writes (§12) mean there's no bundle-creation or normalize step to reconcile.

16. Webmentions

Webmention is the IndieWeb's federated response protocol: likes, replies, and reposts from other sites arrive as cross-site comments. Nothing here is Jam-specific — the plumbing is shared by every post type and Jam inherits it through the base layout and entry-footer.njk. Discovery is shipped; receiving and sending are deferred to the webmention milestone.

PieceStateWhere
Endpoint discoveryshipped (Phase 1)<link rel="webmention" href="https://webmention.io/johanedlund.se/webmention"> in <head> via src/_includes/head/meta-info.njk (jam uses layout: base).
Authorship h-cardshippedThe hidden h-entry block in jam.njk carries u-url, p-name u-url rel="author", and a u-author h-card avatar so a receiver can attribute the post (§5).
Render slotwired, no-opjam.njk → entry-footer.njk → partials/webmentions.njk, currently an empty stub — safe to call while the renderer is empty.

SendingdeferredOutgoing webmentions aren't wired, so a Jam that responds to another post doesn't notify it yet.
