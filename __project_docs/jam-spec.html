Jam

Shipped · Phase 2 · singular jam / plural jams · extracted from live code 22 May 2026

A Jam is a short post sharing music (or other audio) the author is listening to — an album, track, or release, usually linking out to Bandcamp or a streaming service. An IndieWeb "listen" post.

1. Singular / plural identity

Jam is asymmetric: the type is singular, the URL namespace is plural. The Eleventy collection is named with the singular (collections.jam), but the folder, URL, archive, and feed all use the plural.

Note the mismatch: the folder is jams/ but its data file sets category: "jam", and the collection registered from that category is jam (singular). Don't "fix" this — the layout alias, collection, and category are all singular by design.

2. Naming & aliases

JEDEE's music type is named Jam (singular) / Jams (plural), after This Is My Jam — a curated endorsement, not a passive scrobble of whatever happened to be playing. Chosen deliberately over symmetry with reading / watching because the word carries the endorsement.

TermStatusWhere it appears / why
jam / jamschosen nameType, layout, collection, URL, archive, feed, nav (see §1).
listenIndieWeb verb — kept in µf2 + schemaThere is no "jam" microformat: the property is u-listen-of and the planned schema is ListenAction. Jam reuses IndieWeb's listen vocabulary.
listeningprevious name + asset pathThe folder was src/posts/listening/ until Phase 2 renamed it to jams/. The earlier /listening/* /jams/:splat 301 redirect has been removed, freeing the /listening/ namespace for a possible future Listen type (see note). Album art still lives under /assets/images/listening/.
musictopic tagEvery sample carries tags: [music] — a user-facing tag, not the category.

Listen vs. Jam: IndieWeb splits Listen (passive scrobbles — whatever's playing) from Jam (curated picks). If a scrobble feed ever lands it would be a separate Listen type at /listening/, not a rename of Jam.

Canonical vs. live drift

The original spec's canonical names (listen-of, albumArt, year, favoriteTrack, genre[], dateListened) differ from what the live importer emits (source ≈ listen-of, image ≈ albumArt, released ≈ year). Resolution decision (D2): tighten the canonical names but let the Clipper layer emit them; existing samples stay as-is, not migrated.

5. Microformats (µf2)

Emitted by src/_layouts/jam.njk. The listen target is a hidden <data> element (Jams have a visible body, so the target need not be visible):

{% if source %}<data hidden class="u-listen-of" value="{{ source }}"></data>{% endif %}

<div class="e-content">{{ content | safe }}</div>
PropertyClassFrom
Listen targetu-listen-ofsource
Bodye-contentpost content
Publisheddt-publisheddate (via entry-header)
Authorshiph-entry / h-card / u-authorhidden block, meta.author

h-entry nesting caveat: the only h-entry in the layout is the hidden authorship block; the visible u-listen-of + .e-content sit outside it, so a strict parser won't tie them to the entry. Accepted for v1 (webmention sending isn't wired up). Slated for the webmention milestone.

6. Card

The Jams archive does not have a dedicated card. It reuses the shared card-blog.njk (set in jams.njk: cardPartial = "card-blog.njk").

SlotContent
imageitem.data.image (album art), rendered img-square; only if set

Renders a <custom-card clickable img-square> WebC component; styles via css/custom-card.css.

7. Archive page config

src/pages/jams.njk drives the listing through the shared archive-listing.njk partial:

pagination: { data: collections.jam, size: 3 }
permalink:  jams/[page-N/]index.html
cardPartial = "card-blog.njk"
masonryLayout = "50-50"
collectionToPaginate = collections.jam
paginationMetaKey = "blog"

8. Feed

A pair of templates set the same feed variables, then each includes its own format-specific body partial — Atom (jams.xml.njk → feeds/atom-body.njk) and JSON Feed (jams.json.njk → feeds/json-body.njk):

# jams.xml.njk
permalink: /jams/feed.xml
feedCollection = collections.jam
feedTitle = "Jams"
feedDescription = "Music I'm listening to."
feedSelfUrl = "/jams/feed.xml"
→ includes feeds/atom-body.njk

# jams.json.njk — same vars, with:
permalink: /jams/feed.json
feedSelfUrl = "/jams/feed.json"
→ includes feeds/json-body.njk

The permalink: frontmatter (not the filename) controls the output path.

12. Page bundle & co-located cover (planned)

Direction is locked (Clipper-era): each Jam becomes an Eleventy page bundle — a folder named for the slug, holding <slug>.md plus its cover.<ext> and any other co-located assets — instead of a flat .md with the cover in the shared /assets/images/listening/ folder.

src/posts/jams/
└── ep1-by-the-supervoid-choral-ensemble/
    ├── ep1-by-the-supervoid-choral-ensemble.md
    └── cover.jpg            # co-located, referenced as cover: ./cover.jpg
AspectNow (shipped)Planned (bundle)
Post fileflat src/posts/jams/<slug>.mdsrc/posts/jams/<slug>/<slug>.md
Cover storageshared /assets/images/listening/<file>co-located cover.<ext> in the bundle
Frontmatterimage: /assets/images/listening/…cover: ./cover.<ext> + coverSource: (origin URL)
Renderingcard reads imageHTML Transform resolves the relative cover; responsive widths from one source (no coverSmallUrl)

How the cover lands (mechanism not yet resolved): (a) Obsidian Web Clipper downloads it on save if it supports that natively; else (b) a post-process script after each clip; and (c) a one-shot backfill — scripts/colocate-covers.js, modeled on Lene's eleventy-fetch buffer pattern — to migrate existing posts. Gated behind the Clipper layer; nothing has shipped yet.

The page-bundle convention follows Eleventy Excellent's <folder>/<folder-name>.md pattern, so co-locating other per-post assets (not just the cover) uses the same mechanism.

13. Collection registration (wiring)

// src/_config/collections.js
const byCategory = cat => collection =>
  collection.getFilteredByGlob('./src/posts/**/*.md')
    .filter(item => item.data.category === cat)
    .reverse();
export const jam = byCategory('jam');

// eleventy.config.js
import { ... jam ... } from './src/_config/collections.js';
eleventyConfig.addLayoutAlias('jam', 'jam.njk');
eleventyConfig.addCollection('jam', jam);

Category names never enter tags, so "jam" does not pollute /tags/.
